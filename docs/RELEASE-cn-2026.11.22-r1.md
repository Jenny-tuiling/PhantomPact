# 小朋友快乐玩mod：《影之刃零》本地 2–4 人合作 — 2026.11.22 修复构建 r1

适用于《**影之刃零**》（**Phantom Blade Zero**，S-GAME）Windows / Steam 版的**同一台电脑本地 2–4 人**合作扩展包。
**这是同一台电脑多屏多人，不是各人一台电脑联网联机。**

这一版是 11.22 的修复构建（r1），只动设置页和本地底座的诊断，不动游戏逻辑。

## 这一版修了什么

**1. 设置页「选择底座」下拉显示真实名称**
之前下拉是硬编码的旧文案（“本地专用测试版 0.1（尚待实机验收）”），和磁盘上实际的底座（“本地测试版 2026.11.22（交互修正版）”）对不上，看着像没做完的功能。
现在直接读 `BaseVersions/*/manifest.json` 的 `label`，并按磁盘当前底座**预选**对应项。

**2. 应用底座后给出明确结论**
以前点“应用所选底座”如果磁盘已经是该底座，程序直接返回、界面只改一行字，很容易以为没生效。
现在会区分两种情况：
- 已经是它 → “磁盘底座：X　原本就是它，无需切换；下次启动仍按它加载。”
- 真的切换了 → “磁盘底座：X　已切换，下次启动生效。”

**3. 本地底座握手失败时留下证据**
本地底座靠 native 层（`main.dll`）握手确认输入路由可用。以前握手超时只在 UE4SS 日志里写一行，看不到原因。现在：
- 等待期会写 `local_base_status.txt` 的 `waiting` 状态
- 超时（从 10 秒延长到 20 秒）会写 `Mods\PBZCoop\local_base_error.txt`，内容含 nonce、尝试次数、native 实际回复、mod 目录
- 版本串改为前缀匹配，native 端以后升级版本号不会再被误判成握手失败

**4. 清理无关字样**
文档与校验记录里不再出现与本包无关的皮肤名。

## 安装前必看

- **装过旧版必须先卸载**：退出游戏 → 双击旧包里的 `Uninstall.cmd` → 选同一个游戏根目录，然后再装 r1。安装器检测到已安装记录会直接拒绝，这是防止混装的保护。
- 游戏版本仍是 **Steam build 26367565**；不匹配时安装器会停止，别绕过。
- 备份在游戏根目录 `FourPlayerBackups`，卸载器遇到被改动的文件会停下来提示路径，按提示处理。

## 仍然没有解决的问题

- 穿行地图在多人下仍有光标 / 选点问题
- 庞镇切图未实测通过；同时喝药归属、缺席路由、安全复活落点仍有风险
- 猪八戒、枫枫的全动作与场景尚未验收
- 4 人同机（P3/P4）仍需实机验收：这版改的是设置页与诊断，**没有改多人逻辑**

## 关于「本地底座不能用」的排查结论

用你这台机器的运行留痕核对过（`uninstall-backup-20261124-003225`）：

- 握手三件套一致：`probe` / `native` / `status` 都是同一个 nonce，status = `started`，版本 `local-0.1.0`
- `four_status.txt` 里 P1、P2 都拿到了 pawn（`BP_Renewal_Hun_C`）
- `screens.txt` = `party2`，`four_route.txt` 写入了 2 人路由，AI 与恢复钩子状态文件齐全

也就是本地底座当时是**跑通**的。所以这版优先修的是“看不出来发生了什么”的两处界面问题；如果 r1 跑起来仍失败，把 `Mods\PBZCoop\local_base_error.txt` 发出来，能直接定位到 native 层还是 Lua 层。
